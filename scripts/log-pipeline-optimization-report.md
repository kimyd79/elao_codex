# 로그 검증 성능 개선 결과 — 2026-09-28

## 변경 내용

`EALO/backend/loganalyzerapi/parsers.py`에 `split_log_fields()`를 추가했다.
일반적인 공백 구분 필드 및 독립적인 따옴표 필드는 미리 컴파일한 정규식으로 처리한다.
백슬래시 이스케이프, 따옴표와 일반 문자열의 연결, 깨진 따옴표 등은 기존
`shlex.split()`로 처리하여 토큰 및 오류 메시지를 유지한다.
공백 구분 규칙도 shlex와 동일하게 space/tab/CR/LF만 사용한다.
긴 공백이 포함된 잘못된 입력에서 정규식의 과도한 역추적을 피하도록 구성했다.

날짜·상태 코드·바이트·응답 시간 검증과 CSV 생성·DB 적재 로직은 변경하지 않았다.

## 실제 파일 성능

대상: `HOM1-W-F11_500MB.log` (500.63 MiB), 원본 664,076줄.

| 구간 | 기존 (초) | 최종 수정본 (초) |
|---|---:|---:|
| Reading | 2.428 | 2.402 |
| **Validating** | **523.279** | **86.704** |
| Parsing / CSV conversion | 51.587 | 51.218 |
| COPY | 31.568 | 32.516 |
| 저장 건수 조회·검증 | 3.816 | 0.947 |
| 오류 1줄 저장 | 0.0035 | 0.0040 |
| **측정 구간 합계** | **612.682** | **173.790** |

- 검증 단계: **83.43% 단축, 약 6.04배 빠름**.
- 구간 합계: **71.63% 단축, 약 3.53배 빠름**.
- 기존 값은 앞선 측정의 전체 파일 검증 1회와 후속 단계 2회 평균을 조합한 값이다.
- 수정본은 전체 파일을 연속 실행했다. 결과 동일성 확인 등 측정 도구 부가 작업을 포함한
  wall time은 181.062초이며, 위 합계에서는 이 부가 작업을 제외했다.
- COPY는 동일 구조·인덱스의 별도 일반 PostgreSQL 테이블에 수행 후 롤백했다.
  운영 테이블의 기존 크기, 동시 부하, 잠금 대기와 HTTP 비용까지 재현한 값은 아니다.
- 표본 2,000줄 중 1,824줄(91.2%)이 빠른 경로를 사용했고, 나머지는 기존 shlex 경로로 처리했다.

## 기능 유지 확인

- 회귀 테스트 **25개 통과**: Apache/Nginx/IIS/application 로그, 업로드·분석 API,
  동적 스키마, 오류 줄 처리, 누락 허용 기준, COPY 실패 처리 및 V2 모드 포함.
- 짧은 문자열 완전탐색 9,331개 및 고정 시드 생성 입력 6,000개를 기존 shlex와 비교했다.
  추가로 따옴표·이스케이프·Unicode 공백·빈 필드·긴 잘못된 입력·전체 로그 fixture를 비교했다.
- 실제 500 MiB 파일에서 기존 오류 기록과 동일한 위치·원문·오류 코드·메시지 확인.
- 기존 오류 줄을 제외한 기준 로그와 새 검증 출력의 전체 SHA-256 일치:
  `a3947d9f25c826c2bc38b852c5d3c5b6d06bfdb1c016e40bf5039181c51d5f4f`
- 정상 **664,075줄**, 오류 **1줄**, 적재 **664,075줄**로 기존과 동일.
- 측정 종료 후 임시 측정 테이블 0개, 기존 분석 데이터 및 오류 기록 유지 확인.
